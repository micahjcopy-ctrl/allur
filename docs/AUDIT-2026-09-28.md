# ALLUR capability audit, 28 September 2026

## Executive summary

The core loop works end to end: a new user can take the quiz, get a plan, create an account, buy the subscription in the App Store sandbox, land on the dashboard, run a workout, log a meal, get a physique scan and talk to the coach. Every typecheck and every test in the repository passes, the production API answers correctly on all eleven public endpoints checked, and the four builds shipped in the last five days each fixed the bug they were meant to fix.

The app is not ready to submit as it stands, for three reasons that a reviewer will hit. A lapsed iOS subscriber who opens Coach or Nutrition is sent to Stripe Checkout inside the app, which is the exact thing the review notes say does not happen (Apple guideline 3.1.1). The Terms and Privacy links on the paywall open the marketing website inside the app, complete with a Pricing page selling a Premium tier that cannot be bought in the app. And the store listing, the pricing page and the Terms all promise a free tier that new users never get, because every new account is hard-gated to the paywall.

Behind that, the API leaks money and access in five places that were confirmed by calling the endpoints: two coach endpoints run OpenAI calls for anyone on the internet with no login, a third gives free-plan users unlimited coaching, the referral system pays out Premium down a chain from a single purchase, and anyone who registers an address on the admin or comped list becomes an admin or a Premium member with no email verification. Several features the copy promises do not exist (busy-day workouts, injury-aware plans on the funnel, macro changes by the coach, an approve step, rest timers, workout history, native push). Everything is listed below with how it was verified.

## How this was tested

Four passes, each independent of the others.

- Static: TypeScript across every workspace (libs, api-server, fitcoach, scripts) and every test suite (fitcoach 89, nutrition 16, api-server entitlement 13 assertions). One defect found and fixed during the audit: the root typecheck failed on the nutrition test file, which excludes it from the build now.
- Server, live calls: the API was built and run locally against a real Postgres 16 with the production schema and a mock OpenAI, then driven with 109 HTTP checks covering every route: registration and login rules, session handling, the fitness-state blob, every coach endpoint under free, Base and Premium accounts, credit spend, refund and a 10-way concurrency race, the RevenueCat webhook (purchase, expiration, stale events, unknown ids), rate limits, squad, Reps caps, quests, referrals, cron gates, push, admin, support, cardio and account deletion.
- Client, live browser: the production bundle was loaded in Playwright as the iOS shell sees it (native bridge shim, iPhone 15 Pro Max viewport) with a populated demo account and stubbed AI replies, and every screen and core interaction was driven: 74 checks including a full workout, a coach plan update, meal logging, weight and photo logging, a physique scan, cardio manual entry, settings, the lapsed-subscriber paths, save failure and the paywall links.
- Production smoke: eleven public endpoints on www.getallur.com from Chrome (health, prices, push key, auth gates on protected routes, webhook and cron gates).
- Two full read-throughs of the code (client and server) to list what each capability is supposed to do and flag defects by inspection; every flagged item that could be exercised was then exercised above.

Verdicts used below: Works (verified end to end), Works with issues (core path verified, defect noted), Broken (verified failing), Not built (the copy or listing claims it; the code does not do it).

## What must change before "Add for Review"

1. Lapsed-subscriber lock screens send iOS users to Stripe (LockedFeature.tsx:27). Route to /paywall on native. This is the 3.1.1 violation the review notes explicitly deny.
2. Terms and Privacy from the paywall open the marketing chrome (App.tsx:221-238). Render the legal pages bare on native, or open them in the system browser.
3. The "free tier" story. Either give new users the free tier the listing, Pricing page, Terms and index.html describe, or remove those claims before a reviewer follows them into a paywall.
4. Info.plist says photos are saved back to the library; either implement it or drop the key and string.

## Should be fixed in the next builds (money and access)

1. Add auth and credit gating to /coach/personalize-plan, /coach/transcribe, /coach/adapt-plan and /coach/analyze-weight.
2. Email verification, or at least remove the hardcoded comped and admin addresses from source and require a verified email before those lists apply.
3. Referral settlement: reward Base (what was bought), only when the referred user has a real store or Stripe subscription, never on a grant, and refuse loops.
4. Quest uniqueness (a unique index on user plus quest key) and Reps day validation.
5. Account deletion: cancel the real Stripe subscription by customer id, and delete the user's other sessions.
6. RevenueCat webhook: return 200 for ids that are not users; map the lowercase `play_store` value.
7. Set CRON_SECRET in Vercel and drop the User-Agent fallback; add a repeat guard to weekly-recap.
8. Cap message and profile lengths on the coach routes.

## Claims to remove or build

Busy-day 15-minute versions; plan adjusted around injuries on the funnel; "Ask. Approve. Plan updated."; coach changes macros; missed-week recalibration; 14-day free trial; Premium-only voice notes and priority rebalancing; pull to refresh on Squad; "we'll keep retrying"; native notifications; save photos to library; free tier for new users; Base at $12.99 in index.html.

## What is solid

Auth and session handling, input validation on the specified routes, the credit ledger (including under concurrency), the RevenueCat entitlement model (sandbox honoured, expiration, stale-event ordering, lapsed access), rate limiting, the nutrition grounding, the onboarding and purchase funnel, the workout and meal loops, the physique scan and rebalance, error handling on every screen, and the production deployment. The bugs above are real but bounded; none of them is architectural.

## Fixed during this audit

The root `pnpm run typecheck` failed on `lib/nutrition/src/index.test.ts` (bun test types); the test file is now excluded from that package's typecheck. No product code was changed by the audit itself.
